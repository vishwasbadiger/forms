Update Form Refs

Updates page component form references from old andrew paths to correct subfolder paths — no form moves, refs only.

Purpose

When to use this script

The forms package contains all 9 migrated forms (Corporate 1, MI 4, Ratings 1, Energy 5) at their correct new paths. After deploying the package, pages may still have formRef / formPath / guideContainerPath / fileReference properties pointing to old andrew paths. This script updates those references — it does not move or touch any form nodes.

Of the 9 forms, only MI and Energy forms have page refs that need updating — MI forms are referenced from an energy page and a corporate page (cross-BU), energy forms are referenced from energy pages. Corporate and Ratings forms have no page refs.

Pre-requisite

Deploy the forms package first so forms exist at their new paths (mi/forms/ and energy/forms/ci-forms/) before running this script.

How to Run
1

Deploy the forms package

Install the package containing the migrated forms at their new paths. Verify forms exist at mi/forms/ and energy/forms/ci-forms/ in AEM Forms Manager.

2

Dry run first

Open Groovy Console → paste update-form-refs.groovy → set DRY_RUN = true → Run. Review all [DRY] UPDATE lines to confirm the correct refs are being updated.

3

Apply

Set DRY_RUN = false → Run. The script walks the energy and corporate page trees, finds matching old refs, and updates them to new paths. Changes are saved automatically.

4

Validate

Run validate-andrew-migration.groovy to confirm zero stale refs remain. Then run audit-migrated-form-refs.groovy to produce the final evidence log.

Technical Notes

Manual tree walk — no JCR-SQL2 queries. Avoids the 100k node traversal limit on AEM Cloud. Walks page node trees directly via JCR API.

String keys in REMAP — map keys use + concatenation (not "${...}" interpolation) to produce plain Java Strings. This is required because Groovy GString and String have different hash codes — using GString as map keys causes containsKey() to silently return false even when content matches.

Read-only in DRY_RUN mode — node.setProperty() is only called when DRY_RUN = false. All path output is printed in both modes.
