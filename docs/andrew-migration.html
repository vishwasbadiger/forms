Andrew Forms — Migration & Cleanup

Automated removal of legacy "andrew" folder hierarchy across SP Global BUs · AEM as Cloud Service

Background

The Problem

Multiple BUs had Adaptive Forms and DAM assets nested inside folders whose name contained "andrew" (e.g. energy/forms/andrew-en/form-list). These were legacy staging folders that were never cleaned up. Pages across SP Global referenced these paths directly, making a simple folder delete unsafe.

The migration needed to be automated (nearly 100 page references), safe (dry-run first), and per-BU (dev cloud environment instability meant running one BU at a time).

What Changed

How It Works

Migration — 3 Steps

1

Discovery

Recursively walks both AF and DAM trees per BU. When a node with "andrew" in its name is found it distinguishes folders (has child form nodes) from forms (the node itself is the form, e.g. andrew-test-form in Corporate). Builds a move map: old path → new path at BU root.

2

Move Forms

Executes session.move(src, dst) for each discovered form. Skips if the destination already exists. Saves after all moves to keep the session consistent.

3

Delete Empty Folders + Update Refs

Deletes andrew folders once emptied. Then does a manual JCR tree walk (no SQL2 query — avoids the 100k node traversal limit on AEM Cloud) over /content/spglobal/{BU} checking formRef, formPath, guideContainerPath, and fileReference properties. Rewrites any that pointed to an old DAM path.

Scripts
remove-andrew-folders.groovy

Main migration script. Set TARGET_BU and DRY_RUN = true first to preview, then flip to false to apply.

  • DRY_RUN — preview without saving
  • TARGET_BU — run one BU at a time
  • Handles both AF + DAM trees
  • Smart folder vs. form detection
  • No JCR-SQL2 queries (no traversal limit)
validate-andrew-migration.groovy

QA validation script. Read-only — no changes. Run after migration to confirm it's clean.

  • Checks for surviving andrew nodes
  • Scans ~100 page refs for stale "andrew" paths
  • Prints PASS / FAIL summary
  • Lists exact node paths for any failures
QA Checklist

Script scans AF + DAM trees — no node with "andrew" in its name should exist after migration.

🔗

Validation script walks the full page tree and confirms zero formRef / formPath / fileReference values still contain "andrew".

✅

11 forms accessible at new paths

Manually verify each migrated form opens correctly in AEM Forms Manager at its new BU-root path.

Why per-BU execution? AEM as Cloud Service dev environment returned intermittent errors on large-scope runs. Running one BU at a time via the TARGET_BU variable isolates failures and keeps each run fast and recoverable.
