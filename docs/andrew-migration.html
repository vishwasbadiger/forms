Andrew Forms — Migration & Cleanup

Automated removal and reorganisation of legacy "andrew" folder hierarchy across SP Global BUs

Background

The Problem

Multiple BUs had Adaptive Forms and DAM assets nested inside folders whose name contained "andrew" (e.g. energy/forms/andrew-ci-forms/contact-form). These were legacy staging folders never cleaned up. Pages across SP Global referenced these paths directly, making a simple folder delete unsafe.

The migration needed to be automated (nearly 100 page references), safe (dry-run first), and per-BU due to AEM Cloud dev environment instability on large-scope runs.

How It Works — Migration Steps
1

Discovery

Recursively walks both AF and DAM trees per BU. Distinguishes folders (andrew node has child forms) from forms (andrew node is itself the form). Strips andrew- prefix from form names. Builds a move map using BU-specific destination subfolders.

2

Move Forms

Creates any missing intermediate folders (sling:Folder), then executes session.move(src, dst) per form. Skips gracefully if destination already exists.

3

Delete Empty Andrew Folders

After forms are moved, andrew folders are checked for remaining children. Empty folders are removed.

4

Update Content References

Manual JCR tree walk — no SQL2 query (avoids the 100k node traversal limit on AEM Cloud). Scans all 5 in-scope BU page trees (not just the current BU) to catch cross-BU references. Rewrites DAM paths in formRef, formPath, guideContainerPath, fileReference.

Scripts
remove-andrew-folders.groovy
Migration · QA & PROD

Main migration script for environments where andrew folder structure is still intact. Set TARGET_BU and run with DRY_RUN = true first.

  • Per-BU destination subfolder map
  • Strips andrew- prefix from form names
  • Auto-creates intermediate folders
  • Scans all 5 BU page trees for cross-BU refs
  • No JCR-SQL2 queries (no traversal limit)
reorganise-andrew-forms.groovy
Fix · Dev Only

One-time fix for dev environment where forms were incorrectly moved to BU root by the original script. Moves them to correct subfolders.

  • Explicit hardcoded move map (11 forms)
  • BUs: corporate, mi, ratings, energy
  • Auto-creates missing destination folders
  • Updates refs across all 5 BU page trees
validate-andrew-migration.groovy
QA Validation

Read-only post-migration check. Run after each BU migration to confirm clean state.

  • Checks for surviving andrew nodes in AF + DAM
  • Scans all 5 BU page trees for stale refs
  • Prints PASS / FAIL with exact paths
audit-migrated-form-refs.groovy
Audit · Log

Shows which pages currently reference each of the 11 migrated forms at their new paths. Download log for future reference.

  • Checks both AF and DAM new paths
  • Groups results per BU → per form
  • BU-specific or run all at once
QA Checklist
📁

No andrew folders remain

Validation script scans AF + DAM trees — zero nodes with "andrew" in name should exist after migration.

🔗

All ~100 page refs updated

Validation script walks all 5 BU page trees. Zero formRef/formPath/fileReference values should contain "andrew". Cross-BU refs (e.g. energy page → MI form) are included.

✅

11 forms accessible at new paths

Audit script confirms which pages reference each form at its new correct path. Download log as evidence.

Why per-BU execution? AEM Cloud dev environment returned intermittent errors on large-scope runs. The TARGET_BU variable lets you run one BU at a time, isolating failures and keeping each run fast and recoverable. Set to "all" for QA/PROD where the environment is stable.
